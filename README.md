# Shipment ETA Intelligence

A focused prototype for Aiqon's take-home assignment: **Predicting Shipment ETA and Delay Propagation Using AI**.

## What it does
- Generates 300 synthetic shipment journeys with linked delays across stages.
- Predicts total shipment delay at a defined checkpoint: port arrival.
- Converts predicted delay into an estimated final ETA.
- Displays observed upstream delay, simulated congestion/weather indicators and stage delays.
- Reports held-out MAE/RMSE and compares the model with a simple baseline.
- Documents limitations and avoids claiming that synthetic results represent real-world accuracy.

## Quick start

Use Python 3.10+.

```bash
python -m venv .venv
# Windows PowerShell:
.venv\\Scripts\\Activate.ps1
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
python -m src.data_generator
python -m src.train
streamlit run app.py
```

Run tests:

```bash

```

## Prediction definition
The model estimates **total final delivery delay in hours** from information assumed available at the port-arrival checkpoint. Predicted ETA is:

`predicted ETA = scheduled arrival + predicted total delay`

The baseline is observed upstream delay plus the median remaining delay from the training set. The model is a Random Forest Regressor.

## Synthetic data assumptions
- 300 records by default.
- Congestion and weather indicators are simulated values on a 0–1 scale.
- Weather and departure delay affect sailing delay; sailing delay affects port delay; port delay affects customs delay.
- Delays are simplified and non-negative. The simulation does not model all real-world route, carrier, seasonal, transshipment or recovery effects.
- This is a demonstration dataset, not real tracking data.

## Evaluation
Training uses a held-out test split (25%, fixed random seed). Metrics include MAE and RMSE in hours, plus baseline MAE. Actual numbers are generated by `python -m src.train` and saved to `artifacts/eta_model.metrics.json`.

Do not report metrics without running the code. Since the data is synthetic, test performance only measures consistency with the simulation assumptions.

## Limitations and next steps
- No live AIS, port, customs, weather or carrier feeds.
- No calibrated probability of late arrival; the dashboard's “High/Lower” category is a simple threshold, not a probability.
- Explanations describe observed signals and the simulation assumptions; they are not causal explanations from the model.
- A production version should use time-based/route-aware validation, real data, missing-stage handling, prediction intervals, model monitoring and calibrated delay-risk probabilities.
- Improve explanation quality with per-shipment SHAP or carefully validated feature attribution if time and dependencies permit.
